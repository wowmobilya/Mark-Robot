# Clear Arabic and Turkish speech, release 178

## User request

Use the accepted Mark voice, address الأستاذ حسن الحلو instead of Ahmed, offer saved voice controls, and improve report/general-program reading in Arabic and Turkish. Read 0.00 as zero, pronounce amounts by magnitude and currency, and avoid pauses caused by generating the next audio chunk during playback. Latest user steering: speak WOW FURNITURE (Arabic واو فِرْنِتْشَر) instead of Infinity; regenerate the recordings to match, rather than changing only their text.

## Verified constraints

- The application is static and has no hosted TTS backend or credentials.
- Mark can be generated through the authorized production tool and bundled as recordings. There is no available exportable Mark model for arbitrary offline reports.
- Existing local report engines remain separate, visibly named voices. Arabic Nabra is female MSA; Turkish Piper is Fettah. Do not relabel either as Mark or restore the rejected Kareem voice.
- Financial values and report source text remain authoritative and unchanged.

## Implementation

1. Replace all five identity recordings and text with Mark and the requested addressee. Add a second Egyptian Arabic greeting alongside the default Syrian greeting. Store provenance and measured media metadata.
2. Persist enabled state, speed, volume, Arabic greeting dialect, local reading engine preference and continuous playback. Expose preview and stop controls in Robot settings.
3. Normalize validated Arabic and Turkish report snapshots with exact displayed rounding, currency/minor-unit wording and original-source boundary mapping for both local and native playback.
4. Add one shared speech controller and an explicit selected-text reader available across program screens. Only normalize recognized currency amounts; never guess currencies or rewrite business records.
5. Pre-render reports into one bounded PCM/WAV source before playback, with cancellation and progress. Preserve natural pauses from synthesis; do not splice words or numbers from recordings.
6. Bump script/cache versions, validate source integrity/lifecycle/settings and assets, publish atomically and verify deployment.

## Verification

Meaningful automated tests cover displayed zero and negative zero, fractions and large amounts, invalid and mismatched reports, safe numeric bounds, preferences persistence, native/offline routing and source offsets, full-buffer cancellation and replacement, plus selected-text amount parsing. Decode every new MP3 and record its hash/duration. Browser checks cover settings, RTL/mobile header and offline asset availability. Auditory naturalness and actual target-device performance remain device/user checks, not inferred from mocked tests.
