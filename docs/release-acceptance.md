# سجل قبول مارك ربوت لشركة WOW FURNITURE

**في 21 نوفمبر 2026 اكتمل نشر الخلفية وتفعيل المالك للإصدار 213، مع بقاء قبول الأجهزة والمزوّدات ونقل التاريخ مفتوحًا.** النظام مخصص لعمل الشركة الدائم، وعرض التخرج أحد استخداماته. العنوان النهائي `markrobot.wowfurniture.com.tr` يعمل عبر HTTPS برمز `200`؛ العنوان السابق `galeri.wowfurniture.com.tr` يعيد `404` دون تحويل. جُهزت التهيئة العامة بـ`enabled:true` للنشر مع الحزمة النهائية؛ لا يساوي تحضيرها إثبات نشر الواجهة أو قبول هاتف المستخدم. يبقى تطابق 425 ملفًا مع الالتزام الأصلي `39ff395b76f25c5774cf3de2fe15c6d8c5ed9c9d` دليلًا تاريخيًا يخص شيفرة التطبيق الأساسي فقط. ## سجل تفعيل الإصدار 213

نُشرت `wow-cloud` بحالة `ACTIVE` والإصدار 2 وبصمة SHA-256 ‏`9bfc7a5d3eb3aa6c9bab5a018b2cdf3abe88c22491454a92fcb5446e65c21c72`. أُنشئ مالك مخصص ومساحة عمل WOW حية دون استنتاج ملكية من حساب النظام القديم. نجحت **18 تجربة حية** للدخول وتجديد الجلسة والمزامنة وعمليات Storage الخاصة. ونجحت **6 تجارب حية** إضافية: إنشاء إثبات المالك عبر مزوّد Auth، استبداله بجلسة، قراءة الجلسة، رفض تكراره برمز `401`، إغلاق جلسة الاختبار، وبقاء الجلسة الرئيسية صالحة. حُفظت النتائج المنقحة في سجل المشغّل الخاص `markrobot-owner-activation-live-results.json`؛ لا يحتوي هذا المستودع روابط التفعيل أو رموز الجلسات.

طُبّق ترحيل قارئ مفتاح التوقيع في Vault، المحصور بالدور الخدمي. ضُبطت ست خانات في Vault ووظيفة Cron السادسة `wow-push-retry`. أعاد العامل الخاص الموثق `200` مع `sent:0`؛ هذه نتيجة تهيئة وتشغيل، وليست إثبات تسليم إشعار. جُهزت بصمة التوقيع العامة في الواجهة. نجح إصدار قدرة المالك الحية برمز 200 و16 فحصًا بشيفرة التحقق المستخدمة في المتصفح: توقيع ES256 وصلاحية 24 ساعة وربط البصمة والحساب والمساحة والجهاز والإصدار، دون تسريب حقول خاصة. حُفظ السجل المنقح باسم `markrobot-offline-grant-live-results.json`؛ يبقى قبول الجهاز الفعلي منفصلًا. لا تثبت هذه المرحلة استخدام هاتف فعلي أو وصول بريد أو نتيجة نموذج ذكاء أو نقل تاريخ Galeri.TR وبيانات IndexedDB القديمة.

## سجل نشر البنية الخلفية الأول

نجح تطبيق `mark_robot_release_211` بالإصدار `20261121190038` على المشروع المقصود `sldthbnigivpsqixccah` بعد وصول تجربة التراجع الكاملة المنقحة إلى علامة النجاح. ملفات SQL الإنتاجية الاثنا عشر لم تتغير عن خط الأساس المذكور. نُشرت `wow-cloud` بحالة `ACTIVE` والإصدار 1، بالمعرّف `7c82fef5-4e0d-4884-8f6e-fbe217bf0c2d` وبصمة حزمة SHA-256 ‏`9a87e08d382112f7364fa63d0396621ceed20c8bae2b5fd2398acf7747c49805`.

عند `2026-11-21T19:01:27Z` رُصدت النتائج التالية على نقطة Edge المنشورة:

| الفحص | النتيجة |
| --- | --- |
| `GET /health` | `200` مع `ok:true` و`service:mark-robot` و`checkedAt` |
| `POST /health` | `405` |
| `session.snapshot` و`gallery.snapshot` دون توثيق | `401` |
| `OPTIONS` من العنوانين القديم والجديد | `204` مع CORS مطابق للأصل المطلوب |
| طلب من أصل غير مسموح | `403` |
| `POST /push-worker` دون الرمز الخاص | `401` |

أكد تدقيق المرحلة الأولى، قبل تهيئة المالك والأسرار، تطابق الأعداد وبصمات SHA-256 لجميع الجداول القديمة الـ84 وبيانات التعريف لكائنات Storage الـ163. بقيت الحاويات السبع وسياسات التخزين القائمة مطابقة؛ لم تُجلب بايتات الملفات ولم تُحسب بصماتها من جديد. بقيت بصمات مستخدم Auth الموجود وجلساته الـ34 ومشغّله مطابقة. الجداول الجديدة الـ62 جميعها مفعّل فيها RLS؛ الدوال الـ97 لا تمنح `EXECUTE` إلى `anon` أو `authenticated`، والمخططات الخاصة السبعة لا تمنحهما `USAGE`. العروض الستة في `public` تستخدم `security_invoker=true`، والعروض الداخلية الثلاثة خاصة بلا منح للمتصفح. وظائف WOW الخمس في Cron مفعّلة؛ نجحت وظيفة المراسلات عند 19:01 و19:02 UTC دون فشل مرصود، وبقية الوظائف لم تُرصد دوراتها بعد. أعاد فحص الصحة صفر ملاحظات، ولم تظهر أخطاء أو تحذيرات جديدة في الفحص. كان عدد مساحات WOW وحساباتها وخانات أسرارها في Vault صفرًا في ذلك التدقيق الأول؛ غيّرت مرحلة التفعيل اللاحقة هذه الأعداد عمدًا.

هذه أدلة تاريخية على جاهزية البنية وعزل الطلبات وحفظ الحالة القديمة أثناء الإضافة الأولى. لم تكن خطوة النشر الأول قد أنشأت مالكًا أو مساحة WOW أو مفاتيح Web Push؛ أُنجزت هذه التهيئة لاحقًا كما يوضح سجل الإصدار 213 أعلاه. يمكن أن ينجح `/health` دون مساحة نشطة، لذلك يستند قبول الدخول والتخزين إلى التجارب الحية المستقلة، لا إلى استجابة الجاهزية وحدها.

حدّث الالتزام `8e1a5b8` ملف `CNAME` عند `19:02:58Z`. أثبت فحص `19:05:04Z` سجل CNAME إلى `wowmobilya.github.io` بقيمة TTL ‏300 وإصدار منطقة `2026112101`، ونجح HTTP للعنوان الجديد. نجح HTTPS لاحقًا برمز `200`. العنوان السابق يعيد `404` عبر HTTP وHTTPS دون تحويل؛ يبقى نقل بيانات الأصل السابق وقبول التثبيت والمشاركة على الجهاز معلقًا.

## ما اختُبر محليًا وفي GitHub Actions

اجتاز الإصدار 213 النهائي **1620 من 1620 اختبارًا محليًا، دون فشل أو تخطٍّ**، ونجح فحص المصدر: **192 أصلًا و129 برنامجًا نصيًا و4,000,864 بايت**. شملت المجموعة تفعيل المالك وإعادة استخدام الإثبات وانتهاءه وحدود الهوية وإغلاق الجلسة المرشحة، وحذف الجزء السري من الرابط قبل البرامج الأخرى، واستمرار جلسة المالك وعزل دخول الموظف. تاريخيًا اجتاز خط الأساس `c7ea6e7` عدد 1566 اختبارًا وفحص 192 أصلًا و128 برنامجًا نصيًا و3,996,233 بايت؛ ثم نجحت خمسة اختبارات موجهة بعد تصحيح إيصال نقدي اصطناعي في بوابة الإشعارات. يشمل المرور النهائي ذلك الإصلاح، ولم تتغير قاعدة المالية الإنتاجية. البرنامج الحالي وبيانات WOW والأوامر المعلقة تُحفظ طوال النقل. الفحص لا يجيز تصفير المشروع أو حذف جداول أو حسابات أو ملفات، ولا يجعل حذف المستودع القديم خطوة مقبولة قبل مطابقة البيانات والميزات.

### توضيح التنبيهات المالية والتطوير الاختياري

في `accounting.html` العام، يحفظ `saveNotifications()` خياري `notif_overdue` و`notif_salary` دون مسار يرسل تنبيهًا لهما؛ ويعدّل `checkOverdue()` حالة الفاتورة في الذاكرة فقط. يستهلك فحص متصفح كل خمس دقائق `notif_balance` لعرض تحذير منخفض الرصيد أثناء فتح الصفحة. يغطي تحذير الصناديق الأصلي الحالي الوظيفة العملية بعتبات مستقلة ووحدات مالية دقيقة. لم يثبت المصدر العام تذكيرات خادم مجدولة؛ لا يمكن إثبات أو نفي وجود وظائف خاصة غير مرئية دون الوصول إلى المشروع. [مصفوفة المصدر](galeri-feature-merge.md) · [عرض المالية الحالي](../modules/finance/workspace.js)

إضافة تذكيرات خادم اختيارية للفواتير أو الأرصدة أو الرواتب **تطوير جديد غير منفّذ أو مفعّل**، وليست شرطًا لإطلاق الإصدار الأساسي. إشعارات البروفرما والدفعات والمصروفات عند اعتماد الحدث منفّذة بالفعل؛ يبقى قبولها على هاتف مغلق التطبيق ضمن بوابات النشر أدناه.

## ما يحتاج إلى بيانات أو وصول من المالك

- **تشغيل مشروع Supabase والحسابات.** طُبقت البنية الخلفية على `sldthbnigivpsqixccah` واكتملت مطابقة كائنات النظام القديم بعد التطبيق كما هو مسجل أعلاه. أُنجز إعداد مالك WOW ومساحة عمله ومفاتيح الإشعارات والتوقيع، ونجحت تجارب المالك والمزامنة والتخزين الحية. تبقى أدوار الحسابات الأخرى والنسخ والاستعادة وقبول الأجهزة والمزوّدات. يتضمن بيان الإصدار ترتيب ملفات SQL ونقطة Edge. [بيان الإصدار](../supabase/release.json)
- **البيانات الخاصة والأجهزة الحالية.** توفر الملفات العامة الأربع شيفرة الصفحات وعامل الخدمة. يحتاج النقل إلى تصدير مصرح به لجداول Galeri.TR وهوياته وعضوياته وملفات Storage الفعلية، وإلى مزامنة أو تصدير بيانات أجهزة WOW التي استخدمت العنوان القديم. لكل عائلة نسجل العدد قبل النقل وبعده، والمعرّفات غير المحسومة، والمبالغ بكل عملة، وبصمات المرفقات. يُراجع سجل العمل المعلّق على كل جهاز قبل تبديل العنوان. [حدود المصدر](galeri-feature-merge.md) · [عقد المزامنة](cloud-sync-contract.md)
- **البريد والنطاق والمزوّدات.** يلزم وصول مصرح به إلى استضافة النطاق وDNS وصندوق الشركة‏ `info@wowfurniture.com.tr` وإعدادات SMTP، وحساب مزوّد النموذج وأسراره لتجربة التوليد. يتحقق المشغّل من القيم الفعلية داخل حساباتها، ويحفظ الأسرار في إعدادات الخادم. [حالة البريد والنطاق](domain-mail-readiness.md) · [متطلبات المساعد](assistant.md)
