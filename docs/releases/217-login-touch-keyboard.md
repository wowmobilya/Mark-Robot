# Mark Robot 217 — لوحة مفاتيح تسجيل الدخول

## السبب

كانت شاشة الحساب تخفي وتعطّل عناصر الصفحة الموجودة خارج شاشة تسجيل الدخول. أما لوحة المفاتيح المدمجة فكانت تُضاف مباشرة إلى جسم الصفحة؛ لذلك كانت تختفي عند القفل، مع بقاء نافذتها المشروطة مفتوحة وحاجزة للمس. يظهر العطل فور تركيز حقل اسم الدخول على جهاز لمس لأن لوحة الهاتف الأصلية محجوبة عمدًا لصالح لوحة البرنامج.

## التصحيح

- تُفتح لوحة المفاتيح داخل شاشة تسجيل الدخول عندما يكون الحقل تابعًا لها، وتعود إلى موضعها المعتاد عند تحرير حقل من البرنامج بعد الدخول.
- إذا كانت اللوحة موجودة قبل قفل البرنامج، تُزال منها علامة التعطيل التي وضعها قفل الحساب فقط عند نقلها إلى شاشة الدخول. تبقى عناصر العمل الأخرى مخفية ومعطلة حتى توثيق الحساب.
- بقي إدخال كلمة المرور مخفيًا، مع تخطيطات العربية والتركية والإنجليزية والفرنسية والروسية ودعم لوحة الكمبيوتر المعتاد.
- ارتفع إصدار التطبيق والعامل إلى 217، وأصبح عنوان ملف اللوحة `touch-keyboard.js?v=3` لضمان وصول الشيفرة المصححة إلى الأجهزة التي خزّنت الإصدار السابق.

## التحقق

أخفق اختبار الرجوع الجديد أمام شيفرة 216 بسبب بقاء لوحة تسجيل الدخول معطلة، ثم نجح بعد التصحيح. نجحت مجموعة الاختبارات الكاملة **1713/1713**، دون إخفاق أو تخطٍّ، خلال `52542.042754 ms`. وتضمنت **53 اختبارًا** موجّهًا للحسابات ولوحة المفاتيح؛ هذه المجموعة متداخلة ولا تُضاف إلى العدد الكلي.

يستخدم اختبار المتصفح شاشة الحساب وأسلوبها ومزوّد الحساب المحلي الفعلي مع بيانات تجريبية. يختبر اللمس الفعلي لجميع اللغات الخمس، الانتقال إلى كلمة المرور المخفية، إرسال نموذج الدخول، والعودة إلى حقل داخل البرنامج بعد النجاح. يغطي إنشاء اللوحة لأول مرة وإعادة استخدام لوحة سابقة، ويؤكد بقاء الخلفية مقفلة قبل الدخول. أُضيف هذا الاختبار إلى بوابة Chromium في GitHub Actions.

لم يُشغّل Chromium محليًا لأن البيئة رفضت إنشاء المقبس اللازم للعملية. لذلك يُعتمد سجل بوابة المتصفح البعيدة قبل دمج الإصلاح، ويُثبت نشر الالتزام من سجل GitHub Pages بعد الدمج. لا تعني هذه الاختبارات أن هاتف المستخدم نفسه تلقى التحديث أو أن نقل بياناته المحلية اكتمل.
