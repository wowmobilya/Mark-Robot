# Mark Robot

المستودع الأساسي لتطوير برنامج Mark Robot. الموقع الحالي: [markrobot.wowfurniture.com.tr](https://markrobot.wowfurniture.com.tr/).

## حالة المصدر والنشر

- الفرع `main` هو مصدر الموقع الحالي على GitHub Pages، من جذر المستودع. لا يعني تحديث التوثيق تفعيل السيرفر الجديد.
- [الإصدار السحابي](https://github.com/wowmobilya/Mark-Robot/pull/22) مدمج في `main`؛ ملفات `modules/` و`supabase/` أدناه ضمن المصدر الحالي.
- مشروع Supabase المستهدف هو **Mark Robot** بالمعرّف `sldthbnigivpsqixccah`. نُشرت `wow-cloud` بالإصدار 2، وأعاد فحص الخدمة وجلسة المالك `200` في 21 نوفمبر 2026. أعاد فحص المساعد الموثق `provider.configured:false`؛ تهيئة مزود الذكاء وقبول الأجهزة ونقل التاريخ تبقى بنودًا مستقلة في [سجل القبول](docs/release-acceptance.md).
- يحتفظ التطبيق الحالي ببيانات الشركة والمعرض. لا تغيّر النطاق أو تمسح قواعد أو ملفات قديمة، ولا تطبق ترقيات على القاعدة المشتركة قبل استكمال النسخ والاستعادة والجرد والقبول.

[افتح دليل التطوير العربي وروابط الوحدات](دليل%20التطوير/README.md)

## خريطة التطوير

| الجزء | الموقع |
| --- | --- |
| واجهة التطبيق ونقطة الدخول | `index.html`، وملفات JavaScript وCSS في الجذر، و`assets/` |
| الحسابات والمالك والموظفين | `accounts-*.js` والاختبارات المقابلة في `tests/` |
| الأقسام المعيارية للإصدار السحابي | `modules/`، بما فيها المعرض والملفات والمحادثة والمالية والمساعد والمراسلات |
| لوحة إدارة السيرفر | `modules/server/`، مرتبطة بالواجهة عبر `index.html` وسجل `modules/platform/registry.js` |
| واجهة الاتصال والمزامنة والعمل دون اتصال | `modules/platform/` |
| قاعدة البيانات وخدمات السيرفر | `supabase/wow-schema.sql` و`supabase/modules/` و`supabase/functions/wow-cloud/` |
| ترتيب الترقية | `supabase/release.json`؛ لا تطبقه على الإنتاج قبل بوابات التشغيل |
| الاختبارات والتحقق | `tests/` و`scripts/verify-release.mjs` و`.github/workflows/` |
| تعليمات التشغيل والاستعادة | `docs/production-operations.md` و`docs/release-acceptance.md` |

## تعديل أو إضافة أو إزالة وحدة

1. اعمل على فرع منفصل من المصدر الصحيح، وافحص التغييرات القائمة قبل التعديل.
2. أضف واجهة الوحدة إلى `modules/` وفق النمط القائم، وسجلها واربط ملفاتها من `index.html`، مع مراجعة الصلاحيات والترجمات واتجاه العربية.
3. إن احتاجت الوحدة خادمًا، راجع ملفات `supabase/modules/` ومدخل `supabase/functions/wow-cloud/` وترتيب `supabase/release.json`. حافظ على حدود الصلاحيات ولا تضع الأسرار في ملفات الواجهة أو Git.
4. قبل إزالة وحدة، تحقق من الاعتماد عليها ومن ملكية البيانات والملفات. احتفظ بالسجلات التاريخية والنسخ القابلة للاستعادة، ولا تحذف تطبيقات مستقلة.
5. شغّل الاختبارات ذات الصلة و`npm run verify:release` بعد تثبيت الاعتمادات وفق ملفات القفل، ثم سجّل نتائج البيئة الفعلية. اختبارات المحاكاة لا تثبت النشر أو وصول البريد والإشعارات.
6. قبل دمج إصدار الخادم أو تفعيله، نفّذ دليل التشغيل ودفتر القبول، بما في ذلك نسخ قاعدة البيانات وStorage مستقلًا وتجربة استعادتهما ومطابقة المحتوى في بيئة معزولة.

المجلدات والملفات تبقى في أماكنها الحالية حتى لا تنكسر روابط النشر أو التخزين المحلي للأجهزة. اسم المستودع القديم يعاد توجيهه عادةً من GitHub، لكن روابط مواقع GitHub Pages القديمة قد لا تُعاد توجيهها؛ استخدم النطاق المخصص الحالي.
